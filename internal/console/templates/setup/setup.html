The address you open Authentik at. Pre-filled from SCHMERZ_OIDC_ISSUER when it is set; an issuer URL, a trailing slash or an /api/v3 on the end are all fine.

Make one in Authentik: Directory → Tokens and App passwords → Create, intent API Token. There is no way around this step — a first run cannot sign in by OIDC, because the application it would sign in against is what this creates.
It is only needed for setup, so let it expire. It is not kept: the backend mints a non-expiring token of its own, named for this site.
This token can make users in your directory. It never reaches the console's pages, and the backend spends it once.

The application's slug, and the prefix of the administrators' group: {{ .AppName }}-admins. Give a second installation on the same Authentik a different name, or it will find the first one's group, join it, and hand its administrators somebody else's site.
Lowercase letters and digits, with - or _ inside.

The first administrator

Who this site answers to. Leave these blank and it is whoever owns the token — on a fresh Authentik that is akadmin, a bootstrap account rather than a person. An existing account is adopted as it is; a new one is created. Either way they get a single-use link to set up a passkey.

The sign-in redirect is registered as {{ .ConsoleURL }}{{ .CallbackPath }} and matched exactly, so this has to be the address editors really reach the console at.

This takes up to a minute against a remote Authentik. Keep the page open.

What this creates in your directory: an OAuth2 provider, an application, the group {{ .AppName }}-admins, a token for the backend, and — only if your Authentik has none — a recovery flow, bound to the default brand only if the brand has none either. A group for each collective is created when the collective names one.

Anything of these that already exists is reused and brought in line rather than duplicated, and the result page lists every correction. An existing account named as the first administrator is adopted as it is.
